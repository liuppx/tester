# Tester Web 产品目标稿

这份文档是 Web 重构前的对齐稿，描述产品目标、信息架构和交互边界。视觉排版、组件形态和最终文案可在此基础上调整；API 路径和权限语义属于实现契约，不能因视觉调整改变。

## 产品定位

Tester Web 是社区质量门禁的操作台。它让有权限的社区成员完成四件事：确认测试环境是否可用、选择测试范围、查看用例结构、理解项目和依赖关系。它不是产品业务后台，也不负责启动公共中间件。

## 核心用户

| 用户 | 主要任务 | 必须看到的内容 |
| --- | --- | --- |
| 社区成员 | 查看用例和依赖，了解当前质量状态 | 登录状态、环境状态、报告入口、用例脑图 |
| 测试负责人 | 手动触发项目或全量测试 | 测试范围、排队/运行/完成状态、失败报告 |
| Tester 管理员 | 授权或撤销成员 | 待审核身份、授权状态、最近登录时间 |

## 信息架构

```text
控制台 /
├── 钱包身份登录
├── 环境状态与测试操作
├── 用例脑图 /cases
├── 项目依赖图 /architecture
└── 报告 /report/
```

首屏应优先回答“现在能不能测、我能做什么”。登录前只展示身份登录和公开的导航；登录后才展示测试状态、测试范围和操作按钮。管理员入口只对管理员身份显示。

## 页面职责

### 控制台

显示当前身份、测试服务健康状态、全量/单项目选择、排队状态和最近报告。按钮文案要直接表达动作，例如“开始全量测试”“运行 Router 测试”。运行中必须显示不可重复提交的状态；失败时显示可执行的下一步和日志/报告入口。

### 用例脑图

层级固定为“项目 → 功能模块 → 测试用例”。支持项目筛选、编号/标题搜索、模块展开收起、用例详情和已实现/待确认状态。大量节点使用滚动画布；右侧详情面板在桌面端固定，在移动端位于脑图下方。

### 项目依赖图

展示 Tester、Playwright 项目、产品服务、共享中间件和外部软件之间的关系。搜索命中节点时保留相关边；点击节点显示职责、依赖方向和可选依赖。图中不显示 IP、密钥、账号和部署机器身份。

## 已确认的视觉方向

- 主题：质量门禁、运行拓扑、可审计操作。
- 信息密度：桌面端偏密集，保证一次看到状态和动作；移动端优先登录、状态和报告。
- 视觉重点：一个明确的“当前环境状态”锚点，辅以测试范围和最近结果；避免所有内容都做成同样的卡片。
- 状态颜色：成功、运行中、等待授权、失败和待确认必须有文字标签，颜色只做辅助。
- 无障碍：键盘可操作，焦点清晰，减少动效，图中节点提供可读标签。

## 不可改变的前端契约

- 控制服务同源路径：`/api/auth/*`、`/api/status`、`/api/overview`、`/api/cases`、`/api/architecture`、`/api/run`。
- Wallet Identity 使用 Web3-BS，登录成功后由服务端 Secure Cookie 建立会话。
- 未登录只能看到登录入口；用例数据和测试状态必须要求授权会话。
- 管理员授权动作需要服务端 CSRF token，前端不得把 DID 授权逻辑改成只在浏览器判断。
- 页面必须支持 `/report/control/` 部署前缀和 Vite 本地开发代理。

## 已确认的产品决策

1. 首页优先展示质量概览，并显示最近一次全量运行摘要。
2. 用例脑图和项目依赖图作为两个一级入口。
3. 首页纳入历史测试报告入口，并保留报告站点的完整详情。
4. Tester Web 作为独立 `static` 制品发布，服务制品只承载 API 和测试运行器。
